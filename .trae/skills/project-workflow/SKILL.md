# AI 辅助全流程项目落地

## 一、Skill 基础信息

### 1. 核心定位
将沉淀的 5 步项目开发工作流固化为可复用、标准化、AI 友好的执行能力。用户仅需输入项目名称 + 项目核心动因/要解决的问题，即可触发全流程执行，完成从 0 到 1 的项目调研、设计、开发规范制定与落地迭代全链路，大幅降低试错成本，提升 AI 辅助开发的效率与规范性。

### 2. 触发条件
用户输入固定格式内容，即可一键触发本 Skill：
```
我要做的项目：【项目名称】
做这个项目的原因/要解决的核心问题：【详细描述】
```

### 3. 适用范围
- 全品类软件项目（Web 应用、客户端工具、插件、AI 应用等）从 0 到 1 落地
- 个人开发者/小团队 AI 辅助开发场景
- 快速验证产品想法、最小可行性产品（MVP）开发

### 4. 核心交付物
本 Skill 执行完成后，将输出全套标准化项目文档与可落地执行方案：
- RESEARCH.md 需求研究报告
- PRD.md 产品需求文档
- TECH_DESIGN.md 技术设计文档
- AGENTS.md AI 代理开发规范指令
- 分阶段迭代开发执行计划与 AI 提示词包

## 二、Skill 标准化执行全流程（5 步核心工作流）

### 步骤 1：需求研究（Research）- 搞清楚做什么

**执行目标**
30 分钟完成核心调研，明确项目边界，避免重复造轮子，锚定核心价值，为后续所有环节提供决策依据。

**标准化执行步骤（用户输入项目信息后自动触发）**

#### 目标拆解与问题澄清
基于用户输入的项目名称与核心动因，拆解并回答 3 个核心问题：
- 本项目要解决的核心痛点是什么？目标用户是谁？
- 这个痛点是否真实存在？是否有足够的解决价值？
- 项目最终要达成的核心效果是什么？（MVP 阶段要实现的核心结果）

#### 竞品/同类方案调研
调研市面上已有的同类产品/开源项目/解决方案，梳理其核心功能、优势、短板，明确本项目的差异化价值，避免无意义的重复造轮子。

#### 调研结果沉淀
把所有思考与调研结果，写入标准化的 RESEARCH.md 文档。

**强制输出物**
- RESEARCH.md 标准化文档

**AI 辅助提示词模板（直接复制可用）**
```plaintext
我正在做【项目名称】，核心要解决的问题是【项目动因/痛点】。请帮我完成需求研究，输出以下内容：
1. 这个项目的核心目标拆解，明确要解决的核心痛点、目标用户、MVP阶段要达成的核心结果
2. 市面上已有的同类产品/开源解决方案清单，每个方案梳理核心功能、核心优势、明显短板
3. 这个项目可以做的差异化价值点，避免重复造轮子
输出格式清晰，适合直接写入RESEARCH.md文档
```

**校验标准（必须满足才能进入下一步）**
- 明确了项目的核心痛点与目标用户
- 完成了同类方案调研，找到了差异化价值
- 所有内容已沉淀到 RESEARCH.md，无模糊不清的需求

---

### 步骤 2：产品需求文档（PRD）- 明确功能边界

**执行目标**
把需求研究的结果，转化为清晰、无歧义、AI 可理解的产品需求，明确「做什么/不做什么」，是 AI 生成高质量代码的核心依据。

**标准化执行步骤**

#### 核心需求梳理
基于 RESEARCH.md，明确项目的核心业务流程、用户角色、核心功能模块。

#### 功能边界划定
明确「MVP 阶段必须实现的核心功能」、「后续迭代可实现的功能」、「绝对不做的功能」，避免需求蔓延。

#### PRD 文档标准化输出
把需求整理为结构化的 PRD.md 文档，包含产品概述、核心用户流程、功能详情、界面要求、非功能需求等。

**强制输出物**
- PRD.md 标准化文档

**AI 辅助提示词模板（直接复制可用）**
```plaintext
我正在做【项目名称】，需求研究报告见附件【RESEARCH.md内容】。请帮我生成一份标准化的产品需求文档PRD，要求：
1. 清晰说明产品概述、目标用户、核心价值
2. 梳理完整的核心用户操作流程
3. 分模块详细说明MVP阶段必须实现的功能详情，包含每个功能的前置条件、操作流程、预期效果
4. 明确功能边界：必须做的功能、后续迭代做的功能、不做的功能
5. 说明基础的界面交互要求与非功能需求（如性能、兼容性）
输出格式规范、逻辑清晰，AI编程工具可直接基于此文档理解需求生成代码
```

**校验标准（必须满足才能进入下一步）**
- 无模糊不清的需求描述，所有功能都有明确的验收标准
- 清晰划定了功能边界，避免了需求蔓延
- 文档结构化，AI 可直接读懂并执行

---

### 步骤 3：技术设计文档（Tech Design）- 确定技术方案

**执行目标**
基于 PRD，确定项目的技术实现方案，给 AI 明确的技术框架与规范，确保代码结构合理、可维护、可扩展。

**标准化执行步骤**

#### 技术栈选型
基于项目需求，确定前端、后端、数据库、部署方案等核心技术栈，优先选择生态成熟、AI 支持度高的技术栈。

#### 项目架构与目录结构设计
设计清晰的项目分层架构，输出标准化的目录结构，明确每个目录的职责。

#### 数据模型设计
梳理项目需要存储的核心数据，设计数据结构/数据库表结构，明确字段定义与关联关系。

#### 核心技术点与难点预案
梳理项目的核心技术难点，给出初步的解决方案与实现思路。

#### 技术设计沉淀
把所有内容写入标准化的 TECH_DESIGN.md 文档。

**强制输出物**
- TECH_DESIGN.md 标准化文档

**AI 辅助提示词模板（直接复制可用）**
```plaintext
我正在做【项目名称】，PRD文档见附件【PRD.md内容】。请帮我生成一份标准化的技术设计文档，要求：
1. 给出适配本项目需求的技术栈选型建议，包含前端、后端、数据库、部署方案，说明选型理由
2. 设计清晰的项目分层架构与完整的目录结构，明确每个目录的职责
3. 设计项目核心数据模型/数据库表结构，明确字段定义、类型、约束与关联关系
4. 梳理项目的核心技术难点与对应的解决方案
5. 说明接口设计规范与核心业务流程的实现逻辑
输出格式规范，AI编程工具可直接基于此文档生成符合架构要求的代码
```

**校验标准（必须满足才能进入下一步）**
- 技术栈选型适配项目需求，无不合理的技术选择
- 项目结构清晰，职责划分明确
- 核心数据模型与技术难点有明确的解决方案
- 所有内容已沉淀到 TECH_DESIGN.md

---

### 步骤 4：AI 代理指令（AGENTS.md）- 告诉 AI 开发规范

**执行目标**
制定标准化的 AI 开发规则，让所有 AI 编程工具（Cursor、Windsurf、Claude Code、Copilot 等）遵循统一的开发规范，确保生成的代码风格一致、规范、可维护。

**标准化执行步骤**

#### 项目基础信息同步
给 AI 同步项目概述、核心文档索引（RESEARCH.md/PRD.md/TECH_DESIGN.md）。

#### 开发规范制定
明确代码风格、命名规范、注释要求、目录结构遵守规则。

#### 开发与交付要求
明确代码提交规范、测试要求、异常处理要求、安全规范。

#### AI 交互规则
明确 AI 在开发过程中的响应规则、修改要求、问题反馈规则。

#### 规范沉淀
把所有规则写入 AGENTS.md 文档，放在项目根目录，主流 AI 编程工具可自动读取。

**强制输出物**
- AGENTS.md 标准化文档

**AI 辅助提示词模板（直接复制可用）**
```plaintext
我正在做【项目名称】，需求文档PRD.md、技术设计文档TECH_DESIGN.md已完成。请帮我生成一份标准化的AGENTS.md文件，用于指导AI编程工具完成本项目的开发工作，要求：
1. 包含项目概述、核心参考文档索引
2. 明确代码开发规范：命名规范、代码风格、注释要求、目录结构遵守规则
3. 明确开发交付要求：测试要求、异常处理规范、安全编码规范、代码提交规范
4. 明确AI的交互规则：修改代码的要求、问题反馈规则、响应格式要求
内容符合社区通用标准，适配Cursor、Windsurf、GitHub Copilot、Claude Code等主流AI编程工具的自动读取规则
```

**校验标准（必须满足才能进入下一步）**
- 规范无歧义，AI 可直接理解并执行
- 覆盖了代码风格、开发流程、交付要求的核心规则
- 文档放在项目根目录，命名符合社区标准

---

### 步骤 5：实现和迭代（Build）- 小步快跑、逐步完善

**执行目标**
基于前面 4 步的文档，分阶段完成项目开发，小步迭代，快速验证，避免一次性开发带来的风险。

**标准化执行步骤（3 阶段分步迭代策略）**

#### 阶段 1：生成基础项目框架
**核心目标**：完成项目初始化，确保项目可正常启动、环境配置正确

**执行动作**：基于 3 份核心文档，让 AI 生成项目基础框架，完成依赖安装、目录结构创建、环境配置、基础路由/页面搭建

**验收标准**：项目可一键启动，无报错，基础架构符合技术设计文档要求

**AI 提示词模板**：
```plaintext
请基于本项目的 PRD.md、TECH_DESIGN.md、AGENTS.md 文档，完成项目初始化与基础框架搭建，具体要求：
1. 安装所有必要的依赖包
2. 严格按照TECH_DESIGN.md的要求创建完整的目录结构
3. 完成开发环境与配置文件的初始化
4. 创建基础的路由、入口文件与页面框架
5. 确保项目执行启动命令后可正常运行，无报错
完成后给出启动步骤与验证方法
```

#### 阶段 2：核心功能逐个实现
**核心目标**：先跑通核心业务流程，实现 MVP 阶段的所有核心功能

**执行动作**：把核心功能拆分为独立的小模块，按优先级排序，一个一个实现；每完成一个模块，立即进行测试验证，有问题即时修复

**验收标准**：每个功能都符合 PRD 的要求，核心业务流程可完整跑通，无阻断性 BUG

**拆分参考示例**：
1. 第一步：实现核心基类/底层基础能力
2. 第二步：实现第一个核心功能模块，跑通主流程
3. 第三步：实现剩余核心功能模块
4. 第四步：模块联调，跑通完整业务流程

**单功能开发 AI 提示词模板**：
```plaintext
请基于本项目的 PRD.md、TECH_DESIGN.md、AGENTS.md 文档，实现【XX功能模块】，具体要求：
1. 严格遵循已定义的代码规范与项目架构
2. 完整实现该模块的所有功能点，符合PRD中的验收标准
3. 做好异常处理与边界情况兼容
4. 补充必要的注释与单元测试
完成后说明该功能的验证方法与测试用例
```

#### 阶段 3：优化与迭代完善
**核心目标**：优化体验、修复 BUG、完善非核心功能，完成项目交付

**执行动作**：基于测试结果修复 BUG，优化界面交互与性能，补充边缘场景处理，完善项目文档

**验收标准**：项目符合 PRD 所有要求，可正常交付使用
